## 🔥 关键修复

### 1. **防止重复数据（重要！）**

#### 原设计问题：
- ❌ 用户可以重复报名同一活动
- ❌ 用户可以对同一活动重复评价
- ❌ 用户名可以重复注册

#### 优化后：
```sql
-- registrations 表
✅ UNIQUE KEY uk_activity_user (activity_id, user_id)

-- activity_feedback 表
✅ UNIQUE KEY uk_activity_user (activity_id, user_id)

-- users 表
✅ UNIQUE KEY uk_username (username)
✅ UNIQUE KEY uk_mobile (mobile)
```

---

### 2. **查询性能优化（核心！）**

#### 原设计问题：
```sql
-- 慢查询示例（无索引）
SELECT * FROM activities WHERE status = 'approved';  -- 全表扫描
SELECT * FROM registrations WHERE user_id = 123;     -- 全表扫描
SELECT * FROM system_events WHERE user_id = 456 AND status = 'pending';  -- 全表扫描
```

#### 优化后：
```sql
-- 快速查询（有索引）
SELECT * FROM activities WHERE status = 'approved';  -- 使用 idx_status
SELECT * FROM registrations WHERE user_id = 123;     -- 使用 idx_user_id
SELECT * FROM system_events WHERE user_id = 456 AND status = 'pending';  -- 使用联合索引
```

**性能提升预估：**
| 场景 | 原设计 | 优化后 | 提升 |
|------|--------|--------|------|
| 活动列表查询 | ~200ms | ~20ms | **90%** |
| 用户报名记录 | ~150ms | ~15ms | **90%** |
| 通知列表 | ~180ms | ~25ms | **86%** |
| 签到记录查询 | ~300ms | ~30ms | **90%** |

---

### 3. **数据完整性保障**

#### 原设计问题：
- ❌ rating 可以是负数或超过5
- ❌ 缺少字符集导致中文乱码
- ❌ 缺少存储引擎指定

#### 优化后：
```sql
-- 评分约束
✅ CONSTRAINT chk_rating CHECK (rating >= 1 AND rating <= 5)

-- 所有表统一配置
✅ ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```
