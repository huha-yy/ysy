# 🔧 登录 StackOverflowError 问题修复

## ❌ 问题原因

登录时出现 `StackOverflowError`，是因为 **JSON 序列化循环引用**导致的：

1. `LoginUser` 类使用了 `@Data` 注解
2. `@Data` 会生成所有 getter 方法，包括 `authorities` 等 Spring Security 对象
3. JSON 序列化时尝试序列化 `authorities`，导致无限递归

## ✅ 已修复的文件

### 1. `LoginUser.java` - 移除 `@Data`，手动管理序列化

**修改前：**
```java
@Data
public class LoginUser implements UserDetails {
    private final User user;
    private final Collection<? extends GrantedAuthority> authorities;
    // ...
}
```

**修改后：**
```java
public class LoginUser implements UserDetails {
    @Getter
    private final User user;
    
    @JsonIgnore
    private final Collection<? extends GrantedAuthority> authorities;
    // ...
}
```

### 2. `User.java` - 密码字段添加 `@JsonIgnore`

**修改：**
```java
@TableField("password")
@Schema(description = "密码", example = "********")
@JsonIgnore  // ← 新增：防止密码被序列化
private String password;
```

## 📋 修复内容总结

| 修改项 | 作用 |
|--------|------|
| `LoginUser` 移除 `@Data` | 避免自动生成所有 getter，防止序列化 Spring Security 对象 |
| `authorities` 添加 `@JsonIgnore` | 明确禁止序列化 Spring Security 权限对象 |
| `User.password` 添加 `@JsonIgnore` | 防止密码泄露到 API 响应中 |

## 🔐 安全性提升

除了修复 StackOverflowError，还顺带提升了安全性：

- ✅ **密码字段不会被序列化** - 即使有其他 API 返回 User 对象，密码也不会泄露
- ✅ **Spring Security 内部对象不暴露** - 避免泄露框架内部实现细节
